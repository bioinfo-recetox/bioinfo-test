# IB2 website

Source for the Integrative Bioinformatics and Biostatistics group's website
([bioinfo-recetox.github.io](https://bioinfo-recetox.github.io/)), built with
[Quarto](https://quarto.org/). Migrated from the group's previous Hugo +
Wowchemy site (kept for reference under `legacy/`, not part of this site).

## Quick start

Quarto **1.10.18** is pinned for this project (see `_quarto.yml` and
`.github/workflows/publish.yml` — both must always match; see
`MAINTENANCE.md` for how to upgrade).

```
quarto preview   # live-reloading local preview
quarto render    # one-off build into _site/
```

No Python, R or Julia install is needed — Quarto bundles Pandoc, Deno and
Sass, which is all this site uses.

## Where things live

One obvious place per kind of content:

| To change...                     | Edit...                |
|-----------------------------------|-------------------------|
| Team members                      | `people.yml`            |
| Research projects & software tools| `projects.yml`          |
| Publications                      | `publications.bib`      |
| News items                        | `news/*.qmd`            |
| Events                            | `events/*.qmd`          |
| Downloads                         | `downloads.qmd`         |
| Contact info                      | `contact.qmd`           |
| Images                            | `media/`                |
| Site config, navbar, theme choice | `_quarto.yml`           |
| Look and feel (colors, spacing)   | `styles.scss`           |

**See `MAINTENANCE.md`** for the actual step-by-step recipes (add a person,
add a project, add a publication, add a news item, add an event).

`scripts/prepare-data.ts` and the `_generated/` and `_site/` folders are
build output — never edit them by hand, they're regenerated by
`quarto render`/`quarto preview` and are gitignored.

## Design notes

A few structural decisions, in case future-you wonders why:

- **People/Projects/Publications are each one data file** (`people.yml`,
  `projects.yml`, `publications.bib`) rendered into a listing page, rather
  than one file per person/project/paper. Fewer files to keep track of, and
  the whole team/project list or bibliography is visible in one place when
  editing.
- **News and events are one file per item** instead, since each one is a
  standalone, dated piece of writing rather than a data record.
- **Old URLs from the previous site redirect** to their closest new
  equivalent (`aliases:` in each page's front matter), so links from papers
  and grant reports don't break.
